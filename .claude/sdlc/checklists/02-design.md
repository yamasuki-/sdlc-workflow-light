# レビューチェックリスト: 02-design 設計

> 設計は「AI が実装するのに足りる」ことが基準。体裁・網羅性より、実装で迷わないかを見る。

1. すべての SPEC / NFR に対応する設計上の置き場所（モジュール・処理）が分かる
2. モジュールの責務と配置（src_dir 内のパス）が明確で、並行して実装できる程度に分かれている
3. 公開 IF（関数・API・画面ルート）の入出力・エラーが決まっている
4. SPEC の業務ルール・例外・エラー時の振る舞いを、どこでどう扱うかが書かれている
5. データ（テーブル・ファイル・状態）の定義がある
6. セキュリティ（認証・認可の適用箇所、入力検証、秘密情報の扱い）が NFR に沿っている
7. テスト方針: 種別「自動」「両方」の TC をどの単位で自動化するかが決まっている。単体テストの対象が最小限に絞られ、理由がある
8. 過剰設計（仕様に無い機能・将来のための抽象化）が無い
9. project.yaml・rules/common.md の技術スタック・規約と矛盾しない

## プロジェクト固有の観点

このファイルは全プロジェクト共通の本体なので編集しない。プロジェクトで追加する観点（不具合の再発防止を含む）は
`rules/review-<工程ID>.md` に書く（reviewer がこのチェックリストと合わせて確認する）。
