# レビューチェックリスト: 01-specification 要件・仕様

## 要求（REQ / NFR / Q）
1. 取り込んだ SRC がすべて REQ に反映されているか、理由付きで除外されている（trace check）
2. 1 項目 = 1 要求。曖昧語（適切に・なるべく・など）が無く、原文に無い内容を補っていない（補う場合は仮定と Q がある）
3. 曖昧・矛盾・欠落（異常系・権限・データ量・運用）が質問（Q）になっている。Q に「回答が無い場合の仮定」がある
4. NFR はカテゴリを一通り検討し、確かめられる基準値がある。対象外は理由がある

## 振る舞い仕様（SPEC）
5. すべての REQ が SPEC / NFR に展開されている
6. 利用者から見た振る舞いだけを書いている（実装方法・内部構造に踏み込んでいない）
7. 入力（必須・形式・範囲）、正常の振る舞い、業務ルール、**例外・エラー時の振る舞い**、表示・応答が書かれている
8. 権限（誰が使えるか・使えない人が操作したら）が書かれている
9. 仮定に基づく箇所に Q-xxx が付いている。SPEC 間に矛盾・重複が無い

## テスト項目（TC）
10. すべての SPEC / NFR に TC がある（確認しない NFR は対象外の理由がある）
11. TC は仕様だけを見て作られ、正常・異常・境界を含む
12. 確認ポイント（どこを見るか）と期待結果（判定基準）が、人がそのまま見て判断できる具体さで書かれている
13. 種別（手動・自動・両方）の振り分けが妥当（見た目・操作感・文言・業務妥当性は手動、計算・境界の網羅は自動）
14. 手動の TC が多すぎて受入確認の負担が過大になっていない（自動にできるものは自動に）

## プロジェクト固有の観点

このファイルは全プロジェクト共通の本体なので編集しない。プロジェクトで追加する観点（不具合の再発防止を含む）は
