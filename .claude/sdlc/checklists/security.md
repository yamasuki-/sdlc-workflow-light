# レビューチェックリスト: セキュリティ（/sdlc-security で随時実施）

> security-reviewer が使う。該当しない節（LLM 機能・インフラ定義が無い等）は「該当なし」と書く。
> 差分を対象にした場合も、変更箇所から呼ばれる・変更箇所を呼ぶ処理（認証・認可・入力検証の経路）まで確認する。
> セキュリティツール（依存脆弱性・SAST・シークレットスキャン）で検出済みの項目は再判定せず、重大度判定に集中する。

## A. アクセス制御・認証（OWASP A01 / A07）
1. すべての操作・エンドポイントで認可を確認している。他人のリソース ID を指定して参照・更新できない（IDOR）
2. 設計の認可方式（NFR のセキュリティ要件・design.md のセキュリティ）がコードに反映されている
3. セッション・トークンの発行・失効・有効期限、パスワードポリシー、総当たり対策が適切
4. 認可を飛ばす「裏口」（デバッグ用エンドポイント・設計に無い管理機能）が無い

## B. 暗号・秘密情報（A02 / 設定）
1. パスワードは適切な鈍化ハッシュ（bcrypt / argon2 等）。機微データは適切に暗号化されている
2. トークン・セッション ID・ワンタイムコードは暗号論的に安全な乱数で生成している
3. 秘密情報（API キー・パスワード・接続文字列・秘密鍵）がコード・設定ファイル・テストにハードコードされていない
4. 秘密情報は環境変数やシークレット管理の仕組みからのみ取得している

## C. インジェクション・入力検証・出力（A03 ほか）
1. SQL / NoSQL / OS コマンド / LDAP は文字列連結ではなくパラメータ化・安全な API を使っている
2. すべての外部入力（本文・クエリ・ヘッダ・ファイル）をサーバ側で検証している（クライアント側の検証だけに頼らない）
3. 出力先（HTML / JSON / SQL / シェル）に応じたエスケープで XSS 等を防いでいる。テンプレートの自動エスケープを無効化していない
4. CSRF 対策がある（状態を変える要求）。SSTI（入力をテンプレートとして評価しない）・XXE（外部エンティティ無効化）を防いでいる
5. ファイルアップロードの拡張子・MIME・サイズ・保存先パス（パストラバーサル）を検証している
6. オープンリダイレクト・SSRF（入力由来の URL への遷移・要求）を許可リスト等で防いでいる
7. 一括代入（マスアサインメント）で権限項目などを上書きされない（許可する項目を明示している）
8. デシリアライズ対象・署名（JWT の alg 等）を検証している

## D. ログ・エラー・設定（A05 / A09）
1. ログ・エラーレスポンス・例外メッセージに機微情報（個人情報・資格情報・内部パス・SQL）を出していない
2. 認証失敗・認可拒否・重要操作がログに残る。入力をそのままログに書いてログを偽装されない
3. 本番でデバッグモード・詳細スタックトレースを出さない。CORS が無制限でない。Cookie に HttpOnly / Secure / SameSite
4. セキュリティヘッダ（CSP / HSTS / X-Frame-Options / X-Content-Type-Options）をどこで設定するかが明確

## E. ビジネスロジックの悪用・資源枯渇（ツールで見つけにくい。最も注意して見る）
1. 多段の手続き（例: 注文→決済→確定）の途中を直接呼び出して飛ばせない
2. 数量・金額などに負数・ゼロ・極端な値を入れて不正な結果を得られない
3. 「確認してから更新」が並行要求で二重に実行されない（トランザクション・ロック・DB 制約で守っている）
4. ページサイズ・本文サイズ・配列長に上限がある。入力由来の正規表現で破滅的バックトラックが起きない。圧縮爆弾・無制限の外部呼び出しが無い
5. 回数制限が必要な操作（試行・クーポン・招待等）にサーバ側の制限がある

## F. LLM・生成 AI 機能（ある場合のみ。OWASP LLM Top 10）
1. 入力・外部コンテンツ（検索文書・取得した Web ページ）でシステムの指示を上書きされない（指示とデータの分離、出力の検証）
2. 応答を検証・エスケープせずに HTML・SQL・シェル・コード実行に渡していない
3. LLM が呼べる道具・API は最小権限で、破壊的な操作には人の確認がある
4. プロンプトに秘密情報・不要な個人情報を含めていない。検索用ベクタストアに権限による絞り込みがある
5. トークン量・呼び出し回数・費用の上限がユーザ単位で設定されている

## G. 依存ライブラリ・サプライチェーン（全体）
1. 依存脆弱性スキャンの結果に Critical / High が残っていない（ツールが無ければ CI での実行を確認事項にする）
2. ロックファイルがあり、依存のバージョンが固定されている。名前の紛らわしい不審な依存が無い

## H. 横断（モジュール間）
1. 認証・認可・入力検証の実装パターンがモジュール間で統一されている（一部だけ漏れていない）
2. セキュリティ処理が重複実装されていない（共通化の提案）
3. 公開エンドポイントの一覧を俯瞰し、認証不要で公開すべきでないものが無い。モジュール間の信頼境界が適切

## I. インフラ・パイプライン定義（リポジトリにある場合のみ）
1. コンテナを root で動かしていない。ベースイメージのタグを固定している。秘密情報をイメージに含めていない
2. IaC で公開設定・過剰な権限・暗号化無効のリソースが無い
3. CI 定義に秘密情報の平文埋め込み・ログ出力が無い。外部の変更に権限を渡す危険なトリガーを使っていない

## J. NFR のセキュリティ要件との整合
1. NFR のセキュリティ要件（認証方式・認可モデル・暗号・監査ログ・データ保護）ごとに実装箇所を対応付け、未充足が無い

## プロジェクト固有の観点

このファイルは全プロジェクト共通の本体なので編集しない。プロジェクトで追加する観点（不具合の再発防止を含む）は
`rules/review-security.md` に書く（security-reviewer がこのチェックリストと合わせて確認する）。
