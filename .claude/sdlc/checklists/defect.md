# チェックリスト: 不具合対応（/defect）

1. 現象・再現手順が票に書かれ、再現を確認した（NG の TC があれば ID とメモ）
2. 原因が該当箇所（ファイル:行）の粒度で特定され、エビデンス（実行したコマンド・ログ）が票に残っている。推測で書いていない
3. 原因は仕様どおりに作れていないこと（設計か実装の誤り）である。仕様そのものの誤り・不足なら /change に切り替えた
4. 同じ誤りを検出する自動テスト（結合テスト、ロジックなら単体テスト）を追加し、修正前に失敗・修正後に成功することを確認した
5. 修正が原因の範囲に収まっている（`scripts/sdlc trace impact` の範囲外を変更していない）
6. 再確認する TC（retest）が票に書かれ、結果シートで未実施に戻した
7. 同種の不具合を防ぐ観点を `rules/review-<工程ID>.md` に追記した（必要な場合）
